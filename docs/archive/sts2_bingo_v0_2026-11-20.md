# StS2 Bingo — project spec

A Slay the Spire 2 mod that puts a **bingo board inside the game**. The board appears when a run starts, and squares **complete automatically** as the game detects each goal. It works two ways:

- **Solo:** play alone and try to complete a bingo before your run ends. No lobby, no network, works on any run.
- **Multiplayer:** two or more players see the **same board live** and compete for it. In lockout mode, a claimed square **locks** for everyone else.

Both use the same board, goal detection and UI. Multiplayer adds a lobby and an arbiter on top.

Status: idea and feasibility check done (2026-11-20). No code yet.

## 1. Why this, and what already exists

What was checked on 2026-11-20 to make sure this doesn't duplicate an existing mod:

|---|---|---|

| Steam Workshop | Text search (items and collections) for bingo, lockout, bingosync, bingo board, and "bingo" in Chinese, Japanese, Korean and Russian | No bingo mod. Hits were unrelated: "Lucky Relic Reels" (a slot machine), plus two user mod-list collections named "bingo" / "sts2bingoid" that contain no bingo mod |
| GitHub | Repo and code search ("spire bingo", "sts2 bingo", "spire lockout", bingo in C# files using MegaCrit namespaces, 76 Bingosync repos) | One related web app (below). `StS2Aris` has a card named "BingoBoard", but it's a character-mod card. `osrs-spire-bingo` is RuneScape |
| Thunderstore | Community lookup | No StS2 community |
| Web (English and Chinese) | General search | Only StS1's Spire with Friends bingo mode; nothing for StS2 |
| YouTube / Bingosync | StS2 bingo videos | **People already play StS2 bingo by hand** on Bingosync.com: a custom goal list, a randomized board, and clicking squares on the honor system |

**Closest existing project: "Spire Lockout Bingo"** (github.com/sweet115/spire-lockout-bingo, sweet115.github.io/spire-lockout-bingo):
- A **web page**: one `index.html` on GitHub Pages with a Firebase realtime database, built in a single day (2026-10-16), 0 stars.
- Room codes, up to 8 players, Lockout and Bingo modes, 3×3 to 5×5 boards, and a built-in list of 25 StS challenges plus custom challenges.
- **Players claim squares by clicking**, so it's still the honor system. It's not a mod, has no game integration, nothing in-game, and no automatic detection.
- In effect it's a StS-specific Bingosync. It shows people want lockout bingo for StS2, and it covers only the web-board part of this project.

**So bingo as a format exists, as hand-marked web boards (Bingosync, Spire Lockout Bingo). A mod that runs it in-game and marks squares automatically does not.**

What the mod adds over hand-marked web boards:
- No honor system. The game detects each goal.
- No second window. The board is inside the game.
- Hard-to-judge goals get resolved by code, e.g. "do exactly enough damage to win from an elite."
- The board generator is weighted by difficulty, instead of drawing evenly from a pasted list.

Nearby projects, so this one stays different:
- **Spire Race** (github.com/LWFWST/spire-race) does same-seed racing with a Go backend and relay. No bingo.
- **SPIRECRAFT** (Nexus #354) lets you set custom challenges and win conditions. Single-player, no shared board.
- **HollowKnight.BingoSync** auto-marks squares on bingosync.com for Hollow Knight. It shows the auto-marking approach works, in another game.

Before starting, ask once in the StS2 modding Discord whether anyone is already building this.

## 2. Feasibility evidence (checked in the game install, v0.111.1)

- `data_sts2_windows_x86_64\0Harmony.dll` is bundled, so any game method can be patched for goal detection.
- `data_sts2_windows_x86_64\Steamworks.NET.dll` and `steam_api64.dll` are present, and `sts2.dll` references `SteamMatchmaking`, `CreateLobby` and `SteamNetworkingSockets`. A mod running in the game can use Steam lobbies.
- `sts2.dll` has `CUSTOM_AND_SEEDS_EPOCH` and `SeedChangedMessage`, so custom seeds exist and both players can share one.
- The modding setup is mature: BaseLib (Alchyr), the ModTemplate-StS2 wiki, ModSmith, and Workshop support since v0.107.1.
- Existing mods show that the needed pieces work:
  - Overlay UI panels: Timeline #993, Stats the Spire #790, Adventure Log #595.
  - Reading combat events: Timeline, Adventure Log.
  - Custom network messages: SpireChat / sts2_typing.
  - Replacing the multiplayer transport: sts2-lan-multiplayer #579.

**One real unknown:** whether a mod can open its *own* Steam lobby while the player is in a solo run without it clashing with the game's lobby handling. This is spike 2 (section 8). There is a fallback (section 5).

## 3. How it plays

### 3.1 Solo

1. In the Bingo menu (main menu or run setup screen), pick **Solo** and choose:
   - mode: Bingo (a line) / Blackout (whole board) / Score (as many squares as possible)
   - board size: 3×3, 4×4 or 5×5 (5×5 by default)
   - difficulty
   - board seed: from the run seed by default, or a typed-in board code so friends can try the same board on their own
2. Start any normal run (any character, any Ascension, random or custom seed). The board is built when the run starts, using only goals your character can complete.
3. Play normally. Squares mark themselves as the game detects each goal, with a toast and a pulse on the square.
4. Win and lose conditions:
   - Bingo: complete a row, column or diagonal before the run ends.
   - Blackout: fill the whole board before the run ends.
   - Score: no win or loss; your result is the number of squares and lines when the run ends.
   - Dying or finishing the run ends the bingo attempt either way. Winning the run and winning the bingo are separate results.
5. A **results screen** at the end of the run shows:
   - the final board, squares and lines completed
   - the floor and run time when the bingo was completed (or the closest line, if not)
   - the board code, so the same board can be shared
6. **Local history:** past solo boards and results are saved on the player's machine, with personal bests per mode and board size (e.g. fastest bingo by run time and by floor).

Solo needs no Steam lobby and no network. The game itself is the arbiter (section 5).

### 3.2 Multiplayer

1. The host opens the Bingo menu, picks **Multiplayer**, and chooses:
   - mode: Lockout / Standard / Blackout
   - board size: 5×5 by default
   - goal-list version
   - difficulty
   - seed: shared run seed by default
2. The host invites the other players through the Steam overlay. Everyone joins the bingo lobby.
3. Each player starts their own solo run on the same seed (the mod can show the seed so players can copy it).
4. When the run starts, everyone's game builds the **same board** from `(board seed, goal-list version, settings)`. No board data is sent.
5. While playing, a hotkey (default `B`) toggles the board panel. A compact mini-board can stay pinned in a corner.
6. When a player completes a goal, their game sends a **claim**. The **arbiter** (section 5) decides, and everyone's board updates with the claimer's color.
7. Win conditions:
   - Lockout: first to a line (row, column, diagonal) or the majority of squares, depending on the setting.
   - Standard: first to a line.
   - Blackout: first to fill the whole board.
   The winner gets a banner on every player's screen, and the match log stays available.
8. If a player's run ends before the match is decided, they're out but can keep watching the board. Their claimed squares stay theirs.

### 3.3 Shared by both modes
- **Saving and continuing:** board state (seed, settings, claimed squares, detector progress such as "7 of 10 cards played this turn") is saved next to the run. Quitting and using Continue restores the board. In multiplayer, the claim table comes back from the lobby (section 5).
- Same goal list, same detectors, same board UI. The only difference is which arbiter accepts claims.

Later option: **co-op lockout**, with teammates in the same co-op run racing each other for squares. It uses the game's existing multiplayer channel instead of a separate lobby.

## 4. Building the board

- **Generation is deterministic.** `boardSeed = hash(runSeed, goalListVersion, settingsHash)`. Each client generates locally, so nothing about the board is sent.
- **Board codes:** a short code that encodes `(boardSeed, goalListVersion, settings)`. In solo, typing in a code replays a specific board, so friends can compare results on the same board without playing together.
- **Goal list:** a versioned data file (JSON, embedded in the mod). Each goal has:
  - `id`
  - `text` (shown on the square)
  - `difficulty` (1–5)
  - `tags` (`combat`, `deck`, `map`, `shop`, `character:silent`, …)
  - `exclusions` (goals that are too similar, or that contradict this one)
  - `characterReq` (optional)
  - `detector` (the name of the C# detector class)
- **Balance:** use a Bingosync-style "SRL" generator. Every row, column and diagonal should add up to about the same total difficulty. Don't put two goals with overlapping tags in the same line, and respect exclusions.
- **Characters:** remove goals that need a character no player is using, or allow them only when someone picked that character. In solo, only goals your character can complete are used.
- **Version check:** when a player joins, compare `goalListVersion` and the mod version. If they don't match, refuse the join with a clear message.

## 5. Arbiters, live sync and lockout

All claims go through one `IArbiter` interface, so the rest of the mod doesn't know whether it's in solo or multiplayer:

```
IArbiter
├─ LocalArbiter   (solo): accepts every valid claim right away; saves state next to the run
├─ LobbyArbiter   (multiplayer, primary): Steam lobby, owner decides
└─ RelayArbiter   (multiplayer, fallback): Cloudflare Durable Object decides
```

### Solo: the local arbiter
- No network. A claim is accepted as soon as the detector fires, and the board, toasts and win check update right away.
- Board state is saved to a small file next to the run, so it survives quitting and continuing.

### Multiplayer primary: a Steam lobby (no server, $0)
- The host calls `SteamMatchmaking.CreateLobby(k_ELobbyTypeFriendsOnly or Private, maxPlayers)`.
- Lobby **metadata** holds: settings, board seed, goal-list version, and the full claim table (`squareIndex → playerSteamId, timestamp`).
  - Steam syncs lobby metadata to every member automatically, so anyone who joins late or reconnects gets the whole state.
- Players send **claims** to the host as lobby chat messages (`SendLobbyChatMsg`, a small binary or JSON message).
- **Arbiter = the lobby owner.** It handles claims in the order they arrive:
  - Lockout: the first valid claim on a square wins, and later claims on that square are rejected.
  - Standard: every claim is accepted.
  - The owner then updates the claim table in metadata, and every client redraws from it.
- If the host leaves, Steam hands the lobby to another player, and the new owner becomes the arbiter. Store the claim table in metadata, not only in the host's memory, so nothing is lost.

### Multiplayer fallback: a Cloudflare relay
Use this if spike 2 shows the mod's lobby clashes with the game's.
- A Cloudflare Worker with **one Durable Object per match**, connected over WebSocket.
- The Durable Object handles one message at a time, so it naturally decides "who claimed first."
- It fits in the Cloudflare free tier, so it costs $0.
- It also makes a **web spectator view and an OBS overlay** easy (section 8, later ideas).

### Claim message
```
{ match, square, goalId, player, runFloor, combatTurn, clientTime, evidence }
```
`evidence` is a short debug string (e.g. "Block=53 on turn 4, Act 2 floor 22"). It's shown in the match log so people can check claims. It isn't anti-cheat; everyone runs the same mod and is trusted.

## 6. Detecting goals

### Structure
```
GameEvents (Harmony hooks, the ONLY place that knows game internals)
   └─► event bus: CardPlayed, DamageDealt, BlockGained, PowerApplied, CombatStart/End,
                  TurnStart/End, RoomEntered, RelicObtained, PotionBought, HealedFromEvent,
                  DeckChanged, ActCompleted, RunTimerTick, ...
GoalDetectors (pure C#, no game types; take bus events + a RunSnapshot)
   └─► Completed(goalId, evidence)
BingoClient (sends claim to the IArbiter, updates UI)
```

- **Only the hooks layer touches game internals.** When an Early Access patch renames things, only the hooks need fixing, not the detectors.
- Detectors are pure functions or small state machines over events, so they can be **unit-tested against recorded event logs** without starting the game.
- Include a **recorder mode**: the mod writes every bus event to a JSON-lines file during a normal run. Those files become test fixtures.

### Goal difficulty to detect (using goals from a typical hand-run StS2 bingo board)

| How hard to detect | Examples | How |
|---|---|---|
| Event counter | Play 10 cards in a turn · 50+ / 20+ Block · become Confused · heal from an event · 4 debuffs on 1 enemy · buy all potions from one merchant · beat Act 1 boss with 1 relic · finish an act without visiting elites | Count or check per turn, per combat, per act |
| Deck or run state | Fully upgraded deck · deck of only unique cards · empty deck · 10 different buffs · all 4 orb types as Defect · get Artifact/Buffer/Intangible · all non-basic cards unique after Act 1 | Check the snapshot whenever DeckChanged, PowerApplied or ActCompleted fires |
| Sequence or exact value | Do exactly enough damage to win from an elite (overkill = 0 on the killing hit) · play a 1-, 2- and 3-cost card in that order · same number of cards in hand and Exhaust · play no cards on the turn you win a fight | A small state machine; needs damage-before-HP-clamp from the hook |
| Time | Finish Act 2 in at least 0:30:00 | Read the run timer when ActCompleted fires |
| Needs a hand-made card list | Play a Silent finisher card that scales off discards · beat a run using only cards from the same character | Card-ID lists kept in the goal-list file |

**Rule: if the game can't detect a goal, it doesn't go in the goal list.** Nothing is honor-system.

The first goal list (v1) targets about 40 goals from the top three rows of that table. It grows from there.

## 7. In-game UI

- A Godot `Control` panel added to the game's UI root (the BaseLib/ModTemplate wiki shows how).
- Full board: 5×5 grid with goal text, the claimer's color and initials, and a pulse when a square is newly claimed.
- Mini-board: about 120 px in a corner with colored cells only; hover a cell to see its goal.
- Match log: who claimed what, on which floor, with the evidence string. In solo it's a log of your own completed goals.
- Toasts: "Completed *50+ Block*" (solo) or "Opponent claimed *50+ Block*" (multiplayer), and line or win alerts.
- Bingo menu: Solo / Multiplayer choice, settings, board-code entry, and (solo) local history with personal bests.
- End-of-run results screen (section 3.1), shown after the game's own run summary.
- Settings: hotkey, mini-board corner, colorblind-safe player colors.
- Must work with mouse and controller (the game supports both).

## 8. Milestones

1. **Spike 1: hooks and recorder.**
   - Set up the mod project (BaseLib template).
   - Add Harmony hooks for CardPlayed, DamageDealt (with overkill), BlockGained, CombatEnd and DeckChanged.
   - Add a recorder that writes JSONL.
   - Done when one full Act 1 run produces a sensible event log.
2. **Spike 2: Steam lobby from the mod.**
   - Create a friends-only lobby during a solo run, have a second account join, and pass a message both ways while both are in runs.
   - Done when it works, or when the plan has switched to the Cloudflare fallback, with a written reason.
3. **Detectors and tests.**
   - Event bus, about 40 v1 detectors, and unit tests that replay recorded logs.
   - Can be done without the game running.
4. **Board generator.**
   - Goal-list JSON, the balanced generator, determinism tests (same inputs give an identical board), and the version check.
5. **Solo mode, complete.**
   - Full board, mini-board, toasts, `IArbiter` with `LocalArbiter`, saving and continuing, Bingo/Blackout/Score modes, board codes, the results screen, and local history.
   - **This alone is a full release:** solo bingo on any run.
6. **Multiplayer lockout.**
   - `LobbyArbiter` (or `RelayArbiter`), claim messages, rebuilding state from lobby metadata, handling the host leaving, and eliminated players watching.
7. **Multiplayer modes and polish.**
   - Standard and Blackout for multiplayer, win banners, the match log, settings, and colorblind palette.
8. **Release.**
   - Nexus and Workshop pages, a short demo video, and a pitch to StS2 bingo players and creators.

Later ideas:
- A web spectator board and OBS overlay (through the Cloudflare relay)
- Co-op lockout
- 3–4 players and teams
- A community goal-list editor with export
- Seeded "daily bingo" solo boards (board code from the date), with an optional shared leaderboard

## 9. Testing

- **Unit:** each detector against recorded event logs, including tricky cases:
  - overkill exactly 0 vs 1
  - Block gained and then lost in the same turn
  - a goal completed during the final, run-ending combat
- **Determinism:** a property test that the same `(seed, version, settings)` always gives the same board, and that boards respect line-difficulty limits and exclusions.
- **Arbiter:** simulate simultaneous claims, duplicate claims, claims after a win, and the host leaving mid-match. The arbiter logic is pure, so test it without Steam. Run the same claim scenarios against `LocalArbiter` and `LobbyArbiter` to check that solo and multiplayer give the same results where they should.
- **Solo save and continue:** quit mid-combat with a goal half done (e.g. 7 of 10 cards played this turn), continue, and check that the board and detector progress come back.
- **Board codes:** a code round-trips to the identical board, and a code from an older goal-list version gets a clear error.
- **Patch compatibility:** after each game update, replay the stored fixtures, run one short live smoke test with the recorder on, and diff the event shapes.
- **Manual:** a full solo run to a bingo, a two-account lockout match, the UI pass, and controller navigation.

## 10. Risks

| Risk | What to do about it |
|---|---|
| Early Access patches break hooks | Keep hooks in one thin layer; replay fixtures after every update; check game version on load and turn off bingo with a message if it's untested |
| The mod's lobby clashes with the game's Steam lobby code | Spike 2 first; Cloudflare Durable Object fallback |
| Two players claim the same square at the same moment | One arbiter, handling claims in arrival order |
| Different mod or goal-list versions | Check versions on join and refuse with a clear message |
| A goal is ambiguous ("finisher card") | Hand-made card-ID lists; drop the goal if it can't be defined |
| Testing needs two accounts that own the game | Test detectors and arbiter offline; most live testing can be done in solo; multiplayer live tests with a friend or a second PC |
| The game's own save/continue loses mod state | Keep bingo state in the mod's own file next to the run; rebuild it on Continue |

## 11. Stack and constraints

- C# (.NET version as `sts2.runtimeconfig.json` says), Harmony, BaseLib, and Godot UI. MegaDot/ModSmith if a `.pck` is needed for assets.
- $0: solo needs no network at all. Multiplayer uses Steam lobbies for sync, or the Cloudflare Workers + Durable Objects free tier if the fallback is needed.
- Releases on Nexus and the Steam Workshop. Open source on GitHub.
